# 数据、图像与证据维护

## 现有数据

研究快照包括 282 条主表记录、163 条数值坐标、48 条原表包含/隶属关系。
完整主表包括缺坐标记录；地图只展示数值有效的点位。
源坐标系全部待核，不导出声称采用 WGS84 的标准 GeoJSON。
筛选结果可导出 CSV，保留坐标系和审核状态字段。

## 新增或修订条目

1. 在原 Excel/飞书中维护稳定遗产 ID。
2. 修改原表字段；保留来源、原文、自己的解释与待核状态。
3. 导出 Excel 后执行导入脚本。
4. 构建、测试，并查看新增条目。
5. 确认允许的发布范围后再更新线上站点。

不把“包含/隶属”自动解释为军事指挥，也不自动用距离合并同名遗址。

## 添加真实图片

把获准使用的图像放到 `public/media/`，例如 `map-001.jpg`。
在 `data/media.json` 添加对象：

```json
[
  {
    "id": "MEDIA-001",
    "heritage_id": "ZJCD-NB-003",
    "title": "填写真实图名",
    "url": "media/map-001.jpg",
    "source": "填写书名、版本、卷页或收藏机构",
    "license": "填写使用许可或授权说明"
  }
]
```

例子只说明字段，并不声称已经拥有观海卫城的某张原图。
构建后“历史舆图”出现资源卡，可放大阅读。
也可使用 HTTPS 图片地址，但必须允许访问，离线环境无法读取外部图片。
图像查看器不执行配准，也不自动生成古今叠加。

## 后续真正的证据表

建议将每条证据整理为：证据 ID、遗产 ID、书名、版本、卷次页码、原文、
现代解释、审核状态、可公开状态、使用许可。当前 AI 来源粒度是主表记录，
还没有做到卷页级证据引用。后续可据此扩展索引与详情组件。
